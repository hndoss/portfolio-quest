# Blender asset pipeline

See the repo root [`CLAUDE.md`](../../CLAUDE.md) for art direction and the asset
contract, which binds both domains. This file covers authoring only. How the
runtime consumes these assets lives in [`src/CLAUDE.md`](../../src/CLAUDE.md).

Source of truth for every `.glb` in `public/models/props/`.

```bash
npm run models     # build both scenes, write the manifest, render previews
```

## Layout

| Path | Role |
|---|---|
| `lib.py` | Palette, geometry helpers, and the `Prop` contract |
| `build.py` | Entry point. `blender --background --python build.py -- <scene>` |
| `manifest.py` | Merges the per-scene fragments into `src/generated/props.ts` |
| `welcome_hall/` | Scene package: desk plus its counter props |
| `great_hall/` | Scene package: hall seating, tables, hearth irons |
| `*.blend` | Saved scenes, regenerated by the build. Committed. |
| `_preview*.png` | Preview renders, regenerated by the build |
| `_manifest/` | Per-scene fragments. Gitignored intermediate. |

## Adding a prop

One module, one class, one line. There is no second list to remember.

1. Write `<scene>/<prop>.py` with a `Prop` subclass: a `slug`, optionally
   `params`, and a `build()` returning the assembled object.
2. Add an instance to that scene package's `PROPS`.

`build.py` grounds it, exports it, measures it, runs its checks and puts it in
the manifest. The runtime picks it up as a new `PropSlug`.

Scene packages are grouped by room, the way Infinigen groups asset factories by
family — one file per object, not one directory per object. A 20-line prop does
not earn its own folder.

## Adding a scene

Not one line — scenes *are* a second list. Each `build.py` run is its own
process calling `reset()`, so two scenes cannot share one, and the chain in
`package.json` is hand-maintained. A new scene package needs its own
`blender --background --python-exit-code 1 --python build.py -- <scene>` link
in that chain or it never builds and its props never reach the manifest.

## Placement

`welcome_hall` prints three.js-space placements during every build, ahead of the
per-prop metrics. Paste them into `src/components/canvas/WelcomeDesk.tsx` — do
not hand-derive them. Conversion is Blender `(x, y, z)` → three.js `(x, z, -y)`.

## The Prop contract

`build()` returns raw geometry and must **not** call `ground()` — the base class
does that, so a prop cannot opt out of the grounding rule the runtime depends on.

`params` holds the prop's spec numbers in one named dict. This is what makes a
prop reviewable: `(0.032, 0.036)` inside a profile list says nothing, `waist_r`
says what the number is for and what breaks if it moves. Profile point lists are
still raw where no name was ever recorded — naming those means re-cutting the
curve, which moves geometry.

`checks()` yields invariants. The base class checks grounding; override to add
shape rules and `yield from super().checks(obj)` to keep it. **A failing check
does not abort the build** — the preview still renders, so the
edit-rebuild-look loop keeps working on a prop mid-revision — but `build.py`
exits non-zero afterwards, so a violation cannot ship unnoticed.

The envelope rule in `welcome_hall/hourglass.py` is written down but not yet a
check, because the shape violates it today. Fix the shape, then add the check.

## Reviewing a render

Look at the preview before shipping. Dimensions and triangle counts say nothing
about whether a silhouette *reads* — a quill measured perfectly correct and
looked like a bird. Work down this list in order; the top two are the ones that
have actually shipped broken here:

1. **Missing parts** — something in the spec absent from the render.
2. **Floating / disconnected pieces** — parts that should be attached but hover.
3. **Wrong proportions** — sizes that visibly disagree with the intent.
4. **Misalignment** — rotated, offset, or intersecting unnaturally.
5. **Missing detail** — flat where the spec calls for ornament.
6. **Wrong silhouette** — the outline does not read as the object.

## Gotchas that have already cost a round trip

**Build flat shapes along the axis you will rotate about.** A feather built wide
in Z and then rotated about X turns edge-on and renders as a spike. Anything on
the rotation axis is unaffected by that rotation.

**Bevels are expensive.** `soften()` replaces one crease with N rings of
geometry, multiplied across every lathe step. The desk went 46 KB → 284 KB from
bevels alone; dropping the lathe from 40 to 18 segments halved it back with no
visible difference. Keep tessellation lean *before* widening a bevel.

**Report the evaluated mesh.** `obj.data.polygons` excludes modifiers, so raw
triangle counts understate what ships by ~6x on beveled objects. `Prop.export`
already does this.

**Preview lights blow out easily.** The render uses the `Standard` view
transform (not AgX) so colours match the export, which means no highlight
rolloff — over-lit surfaces clip to white and look like the wrong colour.

**Never butt two surfaces at exactly the same coordinate.** Coplanar faces
z-fight into speckle. Sink one part inside the other. The desk body's outer face
sits at 2.95 while every overlay starts at 2.96, and the body runs vertically
past both the plinth and the cornice, so no plane is ever shared.

**The glTF exporter is not deterministic.** Two consecutive builds from
unmodified source produce byte-different `.glb` files — POSITION and NORMAL are
bit-identical, but triangle order and some UV seams shift. So `git diff` on the
models proves nothing, and every `npm run models` dirties all 12 files. To check
whether a change actually moved geometry, compare decoded POSITION/NORMAL
accessors, not bytes or file sizes.

## Style

1. **Layered ornament beats smooth mass.** The desk only started reading as
   furniture once it had a moulded plinth, recessed panels, pilasters, a cornice
   and brass inlay. Stacked chamfers that catch light in bands are what read as
   "carved" at a distance.
2. **Gentle arcs over big radii.** A wide sweep over a small radius reads as a
   round bar no matter how correct the dimensions are — that mistake made the
   welcome desk look like an altar.
3. **Proportions are relative, not literal.** The hourglass is ~2x the bell
   because that is how the pair reads, regardless of real-world sizes.

Geometry is nearing the point of diminishing returns; the remaining gap to the
target is **texture**, which nothing here generates yet.
