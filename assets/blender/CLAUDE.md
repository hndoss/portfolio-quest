# Blender asset pipeline

See `/mnt/shared/development/CLAUDE.md` for global development guidelines.

Source of truth for every `.glb` in `public/models/`. The `.glb` files are
**build artifacts** — never hand-edit them, always regenerate.

```bash
npm run models     # rebuild every .glb + assets/blender/_preview.png
```

## Layout

| Path | Role |
|---|---|
| `lib.py` | Shared helpers and the colour palette. Conventions live here. |
| `welcome_hall.py` | Desk + counter props. Bound for the Office, not the hall. |
| `great_hall.py` | Central Hall furniture: seating, tables, hearth irons |
| `*.blend` | Saved scenes, regenerated by the build. Committed. |
| `_preview*.png` | Preview renders, regenerated by the build |
| `public/models/props/*.glb` | Output, committed |

`npm run models` runs **both** scripts in sequence. Each calls `reset()`, so
they cannot share a scene — adding a third script means adding it to the
chain in `package.json`.

## Conventions

- **1 Blender unit = 1 m = 1 three.js unit.**
- **Every asset is grounded to z = 0** by `ground()`, so React places it at a
  surface height with no per-model offset constant.
- **Assets export at the origin, unrotated.** Placement is React's job.
- Export is glTF 2.0 binary, **+Y up**, modifiers applied.

## Gotchas that have already cost a round trip

**Base colours are LINEAR, not sRGB.** Linear `0.11` displays as sRGB `~0.37`,
so pasting hex values straight in produces washed-out pastels. glTF stores
linear too, so what is in `PALETTE` is exactly what three.js receives. Convert
a target sRGB channel `s` with `((s + 0.055) / 1.055) ** 2.4`.

**Build flat shapes along the axis you will rotate about.** A feather built
wide in Z and then rotated about X turns edge-on and renders as a spike.
Anything on the rotation axis is unaffected by that rotation.

**Always look at the preview render before shipping.** Dimensions and triangle
counts say nothing about whether a silhouette *reads*. A quill measured
perfectly correct and looked like a bird.

**Bevels are expensive.** `soften()` replaces one crease with N rings of
geometry, multiplied across every lathe step. The desk went 46 KB → 284 KB from
bevels alone; dropping the lathe from 40 to 18 segments halved it back with no
visible difference. Keep the tessellation lean *before* widening a bevel.

**Report the evaluated mesh.** `obj.data.polygons` excludes modifiers, so raw
triangle counts understate what ships by ~6x on beveled objects.

**Preview lights blow out easily.** The render uses the `Standard` view
transform (not AgX) so colours match the export, which means no highlight
rolloff — over-lit surfaces clip to white and look like the wrong colour.

## Style

**Target is Arcane / Fortiche painterly fantasy** — see the repo root
`CLAUDE.md`. Rich and ornate, not flat cartoon and not photoreal.

1. **Layered ornament beats smooth mass.** The desk only started reading as
   furniture once it had a moulded plinth, recessed panels, pilasters, a
   cornice and brass inlay. Stacked chamfers that catch light in bands are what
   read as "carved" at a distance.
2. **Gentle arcs over big radii.** A wide sweep over a small radius reads as a
   round bar no matter how correct the dimensions are — that mistake made the
   welcome desk look like an altar.
3. **Proportions are relative, not literal.** The hourglass is ~2x the bell
   because that is how the pair reads, regardless of real-world sizes.

Geometry is nearing the point of diminishing returns; the remaining gap to the
target is **texture**, which nothing here generates yet.

## Overlapping solids

Never butt two surfaces at exactly the same coordinate — coplanar faces z-fight
into speckle. Sink one part inside the other. The desk body's outer face sits at
2.95 while every overlay starts at 2.96, and the body runs vertically past both
the plinth and the cornice, so no plane is ever shared.

## Placement workflow

`welcome_hall.py` prints three.js-space placements at the end of every build.
Paste them into `src/components/canvas/WelcomeDesk.tsx` — do not hand-derive
them. Conversion is Blender `(x, y, z)` → three.js `(x, z, -y)`.

## React side

`src/components/canvas/Prop.tsx` owns all `.glb` loading:

- Each prop gets its **own `<Suspense fallback={null}>`**. A single boundary
  higher up would gate first paint on every prop in the game, because all six
  areas mount at once in `Scene.tsx`.
- `useGLTF` caches by url and returns the *same* object, so the scene is
  **cloned** before use. Without that, a model can only appear once.

## Scene interaction

**The hall runs on two punctual lights**, not the four coloured per-doorway
ones this file used to warn about — those are gone, along with the swamp-green
wash they threw on anything placed near them. What is left is the chandelier at
`[0, 4.45, -1.2]` and the hearth at `[0, 0.8, -4.6]`. Everything else that
glows is emissive.

Two consequences for props:

- **Nothing lights the corners.** A prop far from both lights is carried by
  ambient plus hemisphere alone, so it needs value contrast built into its own
  materials. This is why hall furniture uses `oak` against `wood` rather than
  one wood tone.
- **There is no environment map.** A flat horizontal surface at
  `metalness: 1.0` has nothing to reflect and renders black — the side table's
  first brass inlay did exactly this. Put brass on vertical faces, or on edges
  standing proud, where the key light can catch it.

## Framing

The hall's camera is fixed at `(0, 1.6, 5.2)` with `fov: 75`. Visible
half-width at any depth is `(5.2 - z) * 1.3643`: 14.9m at the north wall, but
only 3.8m at `z = 2.4`. A prop at `|x| > 4` has to sit north of about `z 1.5`
or it is not on screen at all. Check placement against that before modelling
anything for a specific spot.
